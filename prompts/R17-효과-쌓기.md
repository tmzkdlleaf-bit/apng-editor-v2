# R17 — 한 레이어에 효과 쌓기

이미지·글자·도형·움직이는 이미지·그룹 레이어에 효과를 여러 개 순서대로 붙인다. 애프터 이펙트의 "레이어 효과"와 같은 개념이다.
지금의 "효과 레이어"(따로 된 층 + 소스 슬롯)는 그대로 둔다. R16은 끝났다고 가정한다.

## 시작 전에

1. 읽을 파일:
   - `src/core/render/frame.js`(_renderLayer), `layers/image.js`(contentCanvas 캐시 → 변형해서 그리기), `layers/text.js`, `layers/shape.js`, `layers/anim.js`, `layers/group.js`, `layers/instance.js`, `layers/effect.js`
   - `src/core/render/mask.js`, `pool.js`, `cache.js`, `matrix.js`
   - `src/core/anim/params.js`(R16), `src/effects/registry.js`, `src/effects/chromatic.js`·`wave.js`(소스를 받는 효과)
   - `src/ui/inspector/effect-section.js`, `src/ui/effect-gallery.js`, `gallery-modal.js`, `src/ui/inspector/index.js`
   - `src/core/doc/commands.js`(duplicateLayers), `part.js`, `variants.js`
2. 각 leaf 렌더러가 "레이어 자체 좌표(변형 전)의 내용"을 어디서 만드는지 표로 적는다.
   레이어 종류, 내용 캔버스 이름, 크기를 정하는 값, 캐시 키를 칸으로 둔다.
   이미지는 `image.js`의 `contentCanvas`(에셋 크기)다.
3. 표를 보고 아래 설계가 맞지 않거나 너무 크면 **구현 전에 멈추고** R17a/R17b로 나누는 안을 보고한다.

## 데이터 구조

```
layer.fxOrder = ['fx_ab12', 'fx_cd34']          // 위 → 아래 순서로 적용
layer.fx = {
  fx_ab12: {
    effectId: 'glow',
    enabled: true,
    params: {},            // 정적 값
    paramAnim: {},         // R16과 같은 키 구조
    seed: 1,
    mix: { value: 1 },     // 0~1, 효과 섞는 정도(키 가능)
    clip: true,            // 레이어 모양(알파) 안에서만 보이기
  },
}
```

- 배열이 아닌 객체로 둔다. 키 경로가 `fx.<fxId>.paramAnim.<key>`, `fx.<fxId>.mix`가 되어 기존 키 명령을 그대로 쓴다. 순서를 바꿔도 경로가 변하지 않는다.
- 문서 버전 +1. 예전 문서는 `fx`가 없을 뿐이다.

## 렌더 순서 (애프터 이펙트와 같은 순서)

1. 레이어 내용을 **레이어 자체 좌표**의 캔버스에 그린다(변형 전).
2. 효과를 `fxOrder` 순서로 적용한다.
3. 기존 트랙 매트(`layer.mask`)를 적용한다. R21에서 펜 가리기가 여기에 들어온다.
4. 변형(위치·크기·회전) + 카메라를 적용한다.
5. 블렌드·투명도로 합성한다.

- **`fx`가 없거나 모두 꺼져 있으면 지금 경로를 그대로 탄다.** 기존 픽셀 테스트가 전부 그대로 통과해야 한다.
- 레이어 자체 좌표 캔버스 크기:
  - 기본 크기: 이미지 = 에셋 크기, 움직이는 이미지 = 프레임 크기, 글자 = 측정 상자, 도형 = w·h + 테두리
  - 해상도 배율 k = renderScale × max(|scale·scaleX|, |scale·scaleY|). 1보다 작으면 1로 둔다. 긴 변은 4096px를 넘지 않게 한다. 확대해도 흐려지지 않게 하려는 것이다.
  - 가장자리 여백 = 쌓인 효과들의 `bleed` 최댓값 × k
- 그룹·인스턴스는 지금처럼 그룹 작업 캔버스(문서 좌표)에 자식을 그린 다음, 그 캔버스에 효과를 적용한다.
- 공용 함수:
  - `core/render/fx-run.js`의 `runEffect(def, env, params)`: `layers/effect.js`에서 효과를 호출하는 부분을 뽑아낸다(rng, borrow/release, sources, pad). 효과 레이어와 효과 쌓기가 같이 쓴다.
  - `core/render/layer-content.js`: 종류별로 "레이어 자체 좌표 내용"을 만든다. image.js의 contentCanvas 캐시를 재사용한다.
- 효과 종류별 처리:
  - `sources`에 `below`가 있는 효과(색수차·물결 등): 레이어 내용을 소스로 넘기고, 결과로 내용을 **바꾼다**.
  - 그 밖의 효과(빛무리·눈 등): 내용 **위에 그린다**. 효과의 `w,h`는 레이어 기본 크기이고, 좌표 파라미터 0~1은 레이어 기준이다.
  - `clip: true`: 효과를 적용하기 전 내용의 알파로 결과를 자른다(destination-in).
  - `mix`: 결과 = 적용 전 × (1 − mix) + 적용 후 × mix.
- 결정론 규칙: 효과마다 `seed`로 rng를 따로 만든다.
- 렌더 경로에서 캔버스를 새로 만들지 않는다. 모두 pool에서 빌리고 돌려준다.
- 성능: 768×768 문서에서 이미지 1장 + 효과 3개를 쌓았을 때 프레임 렌더 시간을 측정해 `npm run perf`에 항목으로 넣는다. 결과 숫자를 보고한다.

## UI (임시 자리: 속성 패널)

- 모든 레이어 종류의 속성 패널에 "효과" 섹션을 추가한다.
  - [+ 효과]: 기존 효과 갤러리를 연다. 고른 효과가 이 레이어의 쌓기 맨 아래에 추가된다.
  - 효과 카드마다: 켜기/끄기, 이름, 접기, 끌어서 순서 바꾸기, 복제, 삭제
  - 펼치면 파라미터 컨트롤 + 시계 버튼(R16 `key-toggle.js`), 섞기(mix), 레이어 모양 안에서만(clip), 무작위 씨앗(seed)
- `effect-section.js`의 파라미터 자동 생성 코드를 `inspector/effect-params.js`로 뽑는다. 효과 레이어와 효과 쌓기가 함께 쓴다. R23에서 "효과 컨트롤" 패널로 옮길 조각이다.
- 타임라인: R16의 `animatedProps`에 `fx` 파라미터를 추가한다. 라벨은 `효과이름 › 파라미터`.
- 명령: `addFx`, `removeFx`, `moveFx`, `setFx`(patch), `duplicateFx`. 각각 되돌리기 1건.

## 그 밖

- 복제·부품·템플릿·변형: fx id를 새로 바꾸고, `fxOrder`도 같이 바꾼다.
- 클릭 판정(`hit.js`)·선택 상자는 효과 여백을 넣지 않는다(레이어 본체 기준 그대로).
- 썸네일(`timeline/thumbnail.js`)에 효과가 반영되는지 확인하고 보고한다. 반영은 선택 사항이다.

## 테스트 (`tests/r17-fx-stack.spec.js`)

- 효과 없는 이미지 레이어: 렌더 결과가 R16과 픽셀 동일.
- 이미지 + 색수차: 레이어 가장자리 밖은 비어 있고(clip), 안쪽은 색이 어긋난다.
- 이미지 + 빛무리(clip 끔): 레이어 바깥까지 빛이 번진다. 레이어를 옮기면 빛도 같이 옮겨진다.
- 순서 바꾸기 → 결과가 달라진다. 되돌리기 1번에 원래대로.
- 효과 끄기 = 효과 없음과 픽셀 동일. mix 0 = 효과 없음과 픽셀 동일.
- 크기 300%로 확대한 레이어의 효과가 흐려지지 않는다(가장자리 선명도 기준값을 정해 비교하고, 그 값을 보고).
- 그룹에 효과: 자식 전체에 한 번 적용된다.
- 저장 왕복, 복제 후 fx id가 다르다, 미리보기 = 내보내기.
