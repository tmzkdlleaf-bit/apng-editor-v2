# R23d — 전문가 화면 버그 수정 + 재발 방지 + R24 준비

R23b·R23c(커밋 `77a5af9`까지) 결과를 실제 브라우저로 열어 써 보며 검토했다. `npm test` 540개는 모두 통과하지만, **화면에서 실제로 쓸 수 없는 문제**가 있다.
테스트가 이 문제들을 못 잡은 이유는 `toBeVisible()`이 "다른 요소에 가려짐·부모에 잘림"을 검사하지 않고, 콘솔 오류도 보지 않기 때문이다.
이 묶음은 세 부분으로 한다. 부분마다 `npm test`를 통과시키고 커밋한 뒤 다음 부분으로 간다. 보고는 셋을 다 끝내고 한 번 한다.

- **1부 — 화면 버그 수정** (아래 1~6번)
- **2부 — 재발 방지와 화면 사용감** (7~11번)
- **3부 — R24 준비 정리** (12~14번)

CLAUDE.md 규칙과 "전문가판 규칙"을 따른다. 문서 구조(schema·migrate)는 바꾸지 않는다.
너무 크면 STEP 0에서 "1부만 먼저 하고 멈추겠다"고 제안해도 된다. 그때는 이 파일을 다음 번에 2부부터 이어서 쓴다.

# 1부 — 화면 버그 수정
### 1. 메뉴가 펼쳐져도 보이지 않는다 (가장 심각)

- 재현: 1440×900에서 "파일" 클릭 → 드롭다운이 열린 상태(`hidden=false`, 220×252)인데 화면에 안 보인다.
  - 드롭다운 위치에서 `document.elementFromPoint`를 하면 `.toolbar-btn`이 나온다(도구 막대 밑에 깔림).
  - 부모 `[data-region="topbar"]`가 `overflow: hidden`, 높이 48px이라 그 아래로 나간 부분이 잘린다.
- 원인 2: `.menu-dropdown { display: flex }`가 `hidden` 속성을 이겨서, 닫힌 드롭다운 7개가 10px 높이 빈 상자로 메뉴 이름 밑에 계속 보인다(메뉴 아래 둥근 줄무늬).
- 고칠 방향:
  - `.menu-dropdown[hidden] { display: none; }`
  - 드롭다운이 위쪽 막대에 잘리지 않게 한다. 막대의 `overflow`를 풀거나, 드롭다운을 `document.body`에 붙이고 메뉴 버튼 위치로 띄운다. 둘 중 다른 화면(프로젝트 이름 메뉴, 화면 좁을 때)에 부작용이 적은 쪽을 고르고 이유를 보고한다.
  - z-index를 도구 막대·패널·타임라인보다 위로. 숫자를 흩어 쓰지 말고 `tokens.css`에 층 변수(`--z-menu` 등)를 두고 쓴다. 지금 쓰는 z-index 값들을 목록으로 보고한다.
- 프로젝트 이름 버튼 메뉴(`.project-menu`)와 에셋 우클릭 메뉴(`.asset-menu`)도 같은 문제가 있는지 확인한다.

### 2. "새 장면" 창에 스타일이 하나도 없다

- 재현: 파일 › 새 장면 → 창이 가운데 뜨지 않고 페이지 맨 아래에 그냥 글자로 붙는다. 그만큼 앱 화면이 위로 밀려 메뉴 막대·도구 막대가 화면 밖으로 나간다.
- 원인: `newscene-*` 클래스의 CSS가 어느 파일에도 없다(`grep -rn newscene src/styles` 결과 0).
- 고칠 방향: 기존 모달(내보내기 창, `library-modal` 등)과 같은 모양으로 스타일을 만든다.
  - 화면 전체를 덮는 반투명 배경 + 가운데 상자, Esc로 닫기, 바깥 클릭으로 닫기, 열릴 때 이름 칸에 초점.
  - 줄은 "라벨 칸(고정 폭) + 입력 칸" 2열. 크기 프리셋·배경 드롭다운은 상자 폭 안에서 끝난다.
  - `tokens.css` 변수만 쓰고 라이트·다크 둘 다.
- `src/ui/` 안에서 새로 만든 파일 중 CSS가 없는 클래스가 또 있는지 찾는다. 방법: R23b·R23c에서 새로 생긴 `className`/`class="..."` 이름을 모아 `src/styles/`에서 찾고, 없는 것을 목록으로 보고한다. 일부러 스타일이 없는 것(동작용 이름)은 "의도" 표시.

### 3. 아이콘의 원·둥근 사각형이 안 그려진다 (예전부터 있던 버그)

- 재현: 첫 화면을 열기만 해도 콘솔에 `<circle> attribute r: Expected length, "undefined"`, `<rect> attribute rx: ...` 오류가 15개 난다.
- 원인: `icons.js`의 `_buildChildren`이 `'c 7 7 4'`처럼 글자 뒤에 빈칸이 있다고 가정하고 `split(/\s+/)`를 한다. 그런데 아이콘 정의는 `'c7 7 4'`, `'R4 7.5 8 5 3'`처럼 빈칸 없이 써 있다. 그래서 cx 자리에 `'c7'`이 들어가고 r·rx가 `undefined`가 된다.
  - 영향: `zoom-in`(도구 막대 확대 도구 — 돋보기 원이 없어 "+\" 모양), `zoom-out`, `zoom-fit`, `lock`, `unlock`, `duplicate`, `group`, `snap-timeline`, `autokey`, `clock`(R16 키 토글 시계), `settings`, `type-adjust` 등 `c`·`R` 조각을 쓰는 아이콘 전부.
- 고칠 방향: 앞 글자를 떼고 나머지를 나눈다(`piece.slice(1).trim().split(/[\s,]+/)`). 아이콘 정의 문자열은 고치지 않는다.
- 테스트: `iconNames()` 전부를 그려서 마크업에 `undefined`·`NaN`이 없고, 원이 든 아이콘의 `<circle>`에 `r`이 숫자인지 확인. 첫 화면 로드 때 콘솔 오류 0개.

### 4. 이미지를 가져오면 레이어가 저절로 생긴다

- 재현: 프로젝트 탭 "가져오기"로 이미지 1장 → 에셋이 생기면서 화면 가운데에 레이어도 하나 생긴다(`project-panel.js` `_importImage`가 `addLayer`까지 함). 그 뒤 에셋을 화면에 끌어 놓으면 같은 그림 레이어가 2개가 된다.
- 고칠 방향(애프터 이펙트 방식): **프로젝트 탭의 가져오기는 에셋만 추가한다.** 레이어는 끌어 놓거나 더블클릭할 때 만든다.
  - 에셋 줄 더블클릭 → 화면 가운데에 레이어 생성(되돌리기 1건).
  - 파일을 **화면(캔버스)에 바로** 끌어 놓은 경우는 지금처럼 에셋 추가 + 놓은 자리에 레이어 생성.
  - PSD 가져오기도 같은 규칙인지 확인하고, 다르면 맞춘다(PSD는 조각이 여러 개라 "레이어로 펼치기"를 따로 묻는 게 낫다면 그렇게 하고 보고).
  - 이 동작을 가정한 기존 테스트가 있으면 고치고 목록을 보고한다.

### 5. 효과 컨트롤 탭의 수치 줄이 세 줄로 깨진다

- 재현: 이미지에 "빛무리"를 넣고 효과 컨트롤 탭(기본 폭 320)을 보면, 파라미터마다 "이름 한 줄 / 키 버튼+슬라이더 한 줄 / 숫자 칸 한 줄"로 쪼개진다. 이름이 바로 위 파라미터의 숫자 칸 밑에 붙어 있어서 어느 이름이 어느 슬라이더 것인지 헷갈린다.
- 고칠 방향: 한 파라미터 = 한 줄. `[시계·키 버튼] [이름(고정 폭, 넘치면 말줄임)] [슬라이더(늘어남)] [숫자 칸(고정 폭)]`.
  - 좌표(중심 X·Y)는 이름 옆에 숫자 칸 2개, 슬라이더 없음. 색은 이름 옆에 색 칸 + 글자 칸.
  - 폭이 240px 아래로 좁아지면 슬라이더만 숨기고 숫자 칸은 남긴다.
  - 같은 조각을 속성 탭에서도 쓴다면 거기도 같이 맞는지 확인한다.
- "섞기"(mix)는 키를 넣을 수 있는 값이다(R17 `mix: { value }`). 시계 버튼이 없으면 단다.

### 6. 작은 화면 정리

- 화면 아래 줄 "해상도" 라벨이 "해상 / 도" 두 줄로 쪼개진다. 짧은 라벨은 `white-space: nowrap`. 아래 줄·도구 막대·패널 머리 전체에서 같은 문제를 찾는다.
- 화면 오른쪽 아래에 옛 **"보기" 버튼**(`view.js`의 `stage-view-btn`, 그리드·간격·스냅 메뉴)과 **배율 표시 "100%"**(`stage-zoom`)가 남아 있다. 화면 아래 줄과 기능이 겹친다.
  - 그리드 간격·스냅은 "보기" 메뉴(메뉴 막대)와 화면 아래 줄 격자 옆 작은 드롭다운으로 옮기고, 화면 위 버튼·배율 표시는 지운다.
  - 단축키 G(그리드), 스냅 동작은 그대로.

# 2부 — 재발 방지와 화면 사용감

### 7. 모든 테스트에서 콘솔 오류를 잡는다

- 지금 테스트는 콘솔을 보지 않아서, 첫 화면 로드 때마다 나는 아이콘 오류 15개를 놓쳤다.
- 공용 fixture(`tests/helpers/fixtures.js`)를 만든다. Playwright `test.extend`로 `page`를 감싸서 `console.error`와 `pageerror`를 모으고, 테스트가 끝날 때 0개가 아니면 실패시킨다.
- 기존 spec 파일의 `import { test, expect } from '@playwright/test'`를 이 fixture로 바꾼다(전부).
- 일부러 오류를 내는 테스트(잘못된 파일 열기 등)는 그 테스트 안에서만 허용 목록을 둘 수 있게 한다(`allowConsoleErrors(/패턴/)`). 허용 목록을 쓴 테스트를 보고에 적는다.
- 이걸 켜서 새로 드러나는 오류는 고친다. 고칠 수 없는 것(브라우저 경고 등)만 허용 목록에 넣고 이유를 적는다.

### 8. 화면 사진 비교 테스트

- 지금 `npm run screens`는 사진을 찍기만 하고 비교하지 않는다.
- 새 파일 `tests/r23d-visual.spec.js`: Playwright `toHaveScreenshot`으로 아래 화면을 라이트·다크 각각 찍어 기준 사진과 비교한다.
  - 첫 화면(빈 프로젝트), 이미지 1장 + 빛무리 넣은 화면, "파일" 메뉴 연 상태, 새 장면 창, 내보내기 창
  - 1440×900, 1280×720 두 크기
- 흔들림 막기: 애니메이션·깜빡이는 커서 끄기(`animations: 'disabled'`, `caret: 'hide'`), 재생 위치 0 고정, 시간 표시처럼 바뀌는 곳은 `mask`. 허용 차이는 `maxDiffPixelRatio: 0.01`부터 시작.
- 기준 사진은 운영체제마다 글자 모양이 달라 따로 생긴다. GitHub Actions(리눅스)용 기준 사진을 만드는 방법(워크플로에 수동 실행 버튼으로 `--update-snapshots` 돌려 산출물로 받기 등)을 정해 만들고 보고에 적는다. 로컬(윈도우) 기준 사진도 같이 커밋한다.
- 일부러 화면을 바꾼 묶음에서는 `npx playwright test r23d-visual --update-snapshots`로 갱신한다. 이 명령을 CLAUDE.md "실행" 절에 추가한다.

### 10. 처음 열 때 그림판을 화면에 맞춘다

- 재현: 1280×720에서 768×768 새 프로젝트를 열면 100%로 떠서 그림판 위아래가 잘린다. 화면에 맞추기는 Ctrl+0을 눌러야만 된다(`view.js` `_fitToCanvas`).
- 고칠 방향:
  - 프로젝트를 열 때·새로 만들 때·문서 크기를 바꿀 때 자동으로 화면에 맞춘다. 단, 100%보다 크게 키우지는 않는다(작은 문서는 100%로).
  - 사용자가 직접 확대/이동한 뒤에는 창 크기가 바뀌어도 건드리지 않는다. 직접 조작한 적이 없으면 창 크기·패널 크기가 바뀔 때 다시 맞춘다.
  - 맞춘 배율은 편집기 상태다. 문서에 저장하지 않는다.
- 메뉴 "보기 › 화면에 맞추기(Ctrl+0)", "보기 › 100%(Ctrl+1)"가 있는지 확인하고 없으면 단다.

### 11. 그림판·타임라인 높이 나눔과 겹치는 표시 정리

- 재현: 1280×720에서 타임라인이 기본 340px(`shell.css` `--timeline-height`)라서, 레이어가 하나도 없어도 그림판(약 270px)보다 빈 타임라인이 더 크다.
- 경계 끌기(`#tl-resize`)와 높이 기억(`apng2.timelineHeight`)은 이미 있다. 바꿀 것:
  - 저장된 값이 없을 때 기본 높이를 창 높이에 맞춘다: `clamp(180px, 창 높이의 32%, 340px)`.
  - 저장된 값이 있어도 그림판 칸이 최소 280px은 남게 한다(창이 작아지면 타임라인을 줄인다. 저장된 값은 바꾸지 않는다).
  - 경계 손잡이가 눈에 띄지 않으면 마우스를 올렸을 때 선이 진해지고 커서가 바뀌게 한다. 더블클릭하면 기본 높이로 돌아간다.
- 겹치는 표시:
  - 확대 배율이 세 군데 있다: 화면 아래 줄 드롭다운 "100%", 그 옆 숫자 칸 "100 %", 화면 위 "100%"(`stage-zoom`, 6번에서 지움).
    - 숫자 칸이 무엇인지 먼저 확인한다. 확대 배율이면 드롭다운 하나로 합친다(드롭다운에 직접 입력 가능하게). 다른 기능(미리보기 해상도 등)이면 라벨을 붙여 구분하고 보고한다.
  - 프레임 위치 "1 / 24"가 화면 아래 줄 오른쪽 끝과 재생 줄에 두 번 나온다. 재생 줄 것만 남기고 아래 줄에서는 지운다(아래 줄 공간은 다른 것에 쓸 수 있게 비워 둔다).

# 3부 — R24 준비 정리
