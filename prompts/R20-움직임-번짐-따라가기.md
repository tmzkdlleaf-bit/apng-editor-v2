# R20 — 움직임 번짐 + 레이어 따라 움직이기

두 가지를 넣는다. R19까지 끝났다고 가정한다.

- **움직임 번짐**: 빠르게 움직이는 레이어에 잔상 흐림이 생기게 한다(애프터 이펙트의 모션 블러).
- **따라 움직이기**: A 레이어를 B에 연결하면, B가 움직이고 돌고 커질 때 A가 같이 따라간다(애프터 이펙트의 부모 연결).
  지금은 그룹으로 묶는 방법뿐이다.

## 시작 전에

1. 읽을 파일:
   - `src/core/render/frame.js`, `matrix.js`(composeTransforms, applyCamera), `core/render/layer-content.js`(R17), `layers/*.js`
   - `src/core/anim/evaluate.js`, `position.js`(R18), `seam.js`
   - `src/ui/canvas/hit.js`(getDocWorldTr, getParentWorldTr, worldToLocalInParent), `gizmo.js`, `drag.js`, `path-edit.js`, `snap.js`, `align-section.js`
   - `src/ui/canvas/stage.js`(자동 절반 해상도, 재생 중 품질), `src/ui/timeline/layer-list.js`
   - `src/core/doc/commands.js`(removeLayers, duplicateLayers, group, ungroup)
2. "부모 → 자식 월드 변환"을 계산하는 자리를 모두 찾아 목록으로 적는다. 렌더(frame.js)와 UI(hit.js 등)에 따로 있다.

## A. 월드 변환 한 곳으로 (먼저 한다)

- `src/core/anim/world.js`를 새로 만든다:
  - `worldTr(doc, layerId, f)`: 레이어의 문서 기준 최종 변형(카메라 제외)
  - `parentWorldTr(doc, layerId, f)`: 그 레이어의 부모 쪽 변형
- 계산 순서: 그룹 부모 체인 → 따라가기 대상 체인 → 자기 변형.
- 렌더(frame.js)와 UI(hit.js의 getDocWorldTr·getParentWorldTr)가 **모두 이 파일을 쓰게** 바꾼다. 기존 결과와 같아야 한다(기존 테스트 통과).
- R22(그룹 시간)에서 프레임 변환도 여기에 들어온다. 함수 인자 모양을 그걸 감안해서 잡는다.

## B. 따라 움직이기

### 데이터

- `layer.followId = null`를 추가한다. 그룹 소속(`parentId`)과는 별개다.
- 제한:
  - 같은 그룹 안(같은 `parentId`)의 레이어만 대상이 될 수 있다.
  - 자기 자신·자신을 따라가는 레이어(순환)는 막는다.
  - 카메라는 대상이 될 수 없다.
- 따라가는 것: 위치·회전·크기(scale, scaleX, scaleY). 따라가지 않는 것: 불투명도.
- 문서 버전 +1.

### 명령

- `setFollow { id, targetId, keepPlace = true }`
  - `keepPlace`면 연결 순간 화면 위치가 튀지 않게, 현재 프레임 대상 변형의 역변환으로 자기 값을 바꾼다.
  - 키가 있으면 모든 키에 같은 역변환을 적용한다(애프터 이펙트와 같음). 이 방식의 한계를 보고에 적는다.
  - `targetId: null`이면 연결을 해제한다. 이때도 화면 위치를 유지한다.
- 대상 레이어를 지우면 따라가던 레이어는 해제한다(위치 유지). 복제하면 범위 안의 `followId`를 새 id로 바꾼다.
- 그룹 묶기·풀기로 대상과 다른 그룹이 되면 해제한다(위치 유지). 해제된 레이어가 있으면 안내한다.

### UI (임시 자리)

- 레이어 목록 줄에 "따라가기" 칸을 둔다. 드롭다운으로 같은 그룹 레이어를 고른다.
  - 애프터 이펙트의 "끌어서 연결(pick whip)"은 R24에서 넣는다.
- 속성 패널 위치 섹션에도 같은 드롭다운을 둔다.
- 따라가는 레이어를 화면에서 끌기·회전·크기 조절할 때 대상의 변형이 반영돼야 한다(drag.js가 world.js 사용).
- 스냅·정렬(snap.js, align-section.js)이 월드 위치 기준으로 동작하는지 확인한다.

## C. 움직임 번짐

### 데이터

- 문서: `doc.meta.motionBlur = { on: false, shutter: 180, phase: -90, samples: 8 }`
  - `shutter`: 셔터 각도. 360이면 한 프레임 전체를 번지게 한다.
  - `phase`: 시작 위치.
  - `samples`: 쪼개 그리는 횟수.
- 레이어: `layer.motionBlur = false`. 문서와 레이어 스위치가 **둘 다 켜져야** 번진다(애프터 이펙트와 같음).
- 문서 버전은 B와 같이 한 번만 올린다.

### 렌더

- 번짐이 켜진 leaf 레이어:
  1. R17의 "레이어 자체 좌표 내용"을 프레임 f에서 **한 번만** 만든다(효과까지 적용한 상태).
  2. 변형만 하위 프레임으로 바꿔 가며 N번 그린다.
     - 하위 프레임 = f + (phase + shutter · i/(N−1)) / 360, i = 0..N−1
  3. N번을 평균 낸다(각각 알파 1/N로 'lighter' 누적 또는 그에 맞는 방법). 8비트 반올림 오차를 보고한다.
  4. 그다음 기존처럼 블렌드·투명도로 합성한다.
- 내용(글자 한 글자씩 애니메이션, 움직이는 이미지 프레임, 효과)은 하위 프레임으로 바꾸지 않는다. 변형만 바꾼다. 이 한계를 보고에 적는다.
- 하위 프레임이 0보다 작거나 frameCount 이상일 때:
  - 재생 방식이 반복이면 frameCount로 나눈 나머지를 쓴다(이음새가 매끄럽게).
  - 핑퐁은 반사, 한 번은 끝에서 멈춤.
- 그룹 스위치: 그룹 자체는 번지게 하지 않는다. 그룹 스위치를 켜면 UI에서 자식 전체 스위치를 켜는 편의 동작만 한다.
- 효과 레이어·보정 레이어는 번짐 대상이 아니다.
- 결정론: 하위 프레임 계산에 난수를 쓰지 않는다.
- 성능: 미리보기 재생 중·절반 해상도일 때는 samples를 3으로 줄인다. 내보내기는 항상 설정값을 쓴다.

### UI (임시 자리)

- 타임라인 머리에 "움직임 번짐" 문서 스위치 버튼을 둔다. 캔버스 설정 창에 셔터 각도·시작 위치·쪼개기 수 칸을 둔다.
- 레이어 목록 줄에 번짐 스위치를 둔다.

## 테스트 (`tests/r20-blur-follow.spec.js`)

- world.js 교체 후 기존 테스트 전부 통과.
- 따라가기: 대상이 오른쪽으로 100 이동하면 자식 화면 위치도 100 이동. 대상이 90도 돌면 자식이 대상 기준점 둘레로 돈다.
- keepPlace: 연결·해제 순간 화면 위치가 같다(0.5px 이하).
- 순환 연결 거부, 대상 삭제 시 해제 + 위치 유지, 복제 시 id 바뀜.
- 번짐: 빠르게 움직이는 사각형의 가장자리 반투명 폭이 이동 거리 × shutter/360에 가깝다. 멈춘 레이어는 번짐 없음 = 픽셀 동일.
- 반복 문서에서 f0 번짐 결과와 f=frameCount 결과가 같다(이음새).
- 문서 스위치 끔 = 기존과 픽셀 동일. 미리보기 = 내보내기(같은 samples).
