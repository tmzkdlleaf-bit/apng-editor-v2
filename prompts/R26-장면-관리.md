# R26 — 여러 장면(컴포지션)

한 프로젝트 안에 크기·길이가 다른 장면을 여러 개 두고, 장면을 다른 장면 안에 레이어로 넣는다.
애프터 이펙트의 "컴포지션 / 프리컴포즈"와 같다. 예: 주사위 컷인 장면을 만들어 결과 화면 장면 3곳에 넣기.
R25까지 끝났다고 가정한다.

## 시작 전에

1. 읽을 파일:
   - `src/core/doc/schema.js`, `commands.js`, `store.js`, `part.js`, `variants.js`
   - `src/core/io/migrate.js`, `project-file.js`, `autosave.js`, `idb.js`, `snapshots.js`
   - `src/core/render/frame.js`, `layers/group.js`, `layers/instance.js`, `core/anim/world.js`, `time.js`(R22)
   - `src/ui/editor-state.js`, `src/ui/timeline/*`, `src/ui/canvas/*`, `src/ui/shell/shell.js`
   - `src/ui/export/index.js`, `set-tab.js`, `src/core/export/bake.js`
2. `doc.order`·`doc.meta`를 직접 읽는 곳을 모두 찾아 개수와 파일 목록을 보고한다.
3. 이 묶음은 가장 크다. STEP 0에서 나누는 안을 보고하고 멈춘다(예: R26a 데이터·렌더, R26b 편집 화면·탭, R26c 내보내기·묶기 명령).

## 데이터 구조

```
doc.comps = {
  main:   { name: '장면 1', meta: { width, height, frameCount, background }, order: [...] },
  cmp_x1: { name: '컷인',   meta: { ... }, order: [...] },
}
doc.mainComp = 'main'     // 내보내기·처음 열기 기준
doc.layers = { ... }      // 모든 장면의 레이어가 한 사전에 있다(id 전역 유일)
```

- fps는 프로젝트 전체에서 하나만 쓴다(`doc.meta.fps`). 장면마다 다르게 하지 않는다. 이 제한을 보고에 적는다.
- 카메라: 장면마다 둔다(`comps[id].camera`).
- 새 레이어 종류 `'comp'`: `{ compId, time: {...R22와 같은 형식} }` + 일반 변형·효과·가리기
  - 그룹과 다른 점: 그 장면의 크기로 잘린 캔버스에 그린 뒤, 그 캔버스를 하나의 레이어처럼 변형한다.
- 순환 금지: A 안에 B, B 안에 A 불가. 자기 자신 불가.
- 마이그레이션: 버전 +1.
  - 기존 `doc.meta`·`doc.order`·`doc.camera` → `comps.main`
  - **호환을 위해** `doc.meta`·`doc.order`는 읽기 전용 별칭으로 남길지, 모든 호출을 바꿀지 STEP 0에서 판단해 보고한다. 2단계 목록을 근거로 한다.

## 렌더

- `renderFrame(ctx, doc, f, { compId })`. 기본은 `doc.mainComp`.
- comp 레이어 렌더:
  1. pool에서 그 장면 크기 × renderScale 캔버스를 빌린다.
  2. 하위 장면을 안쪽 프레임(R22 `innerFrame`)으로 렌더한다.
  3. R17 레이어 자체 좌표 경로(효과·가리기·움직임 번짐)를 그대로 탄다. 기본 크기 = 장면 크기.
- 하위 장면 결과는 (장면 id, 안쪽 프레임, renderScale, 그 장면 문서 변경 번호)가 같으면 같은 프레임 안에서 재사용한다. 같은 장면이 3번 들어가도 한 번만 그린다.
- 결정론·루프 규칙 그대로.

## 편집 화면

- `editorState.activeComp`: 지금 열려 있는 장면이다.
  - 화면·타임라인·속성·클릭 판정·스냅·추가 명령이 모두 이 장면 기준이다.
- 화면 위 장면 탭: 열린 장면들, 닫기, 순서 끌기. 탭 줄 왼쪽에 "상위 장면 › 하위 장면" 경로를 표시한다.
- comp 레이어 더블클릭 → 그 장면 탭을 연다.
- 프로젝트 패널(R23)에 장면 목록을 보여준다. 끌어서 다른 장면에 놓으면 comp 레이어가 생긴다.
- "장면 설정" 창(R23 새 장면 창 재사용): 이름·크기·길이·배경을 바꾼다.
- 되돌리기 기록은 프로젝트 전체에서 하나다. 장면을 오가도 순서대로 되돌린다.
- 그룹 시간 remap 안내(R22)의 "그룹을 열어 편집"은 이 기능으로 대체한다. 그룹 → 장면 바꾸기 명령을 제공한다.

## 명령

- `addComp`, `removeComp`(쓰이는 곳이 있으면 거부하고 사용처를 안내), `setComp`
- `precompose { ids, name, moveAttributes }` = 장면으로 묶기 (Ctrl+Shift+C)
  - 고른 레이어를 새 장면으로 옮기고, 그 자리에 comp 레이어를 하나 둔다.
  - 새 장면 크기·길이는 현재 장면과 같게 한다.
  - 화면 결과가 묶기 전과 픽셀 동일해야 한다.
- `compFromGroup { groupId }`: 그룹을 장면으로 바꾼다. 결과 픽셀 동일.
- `duplicateComp`: 장면 복제. 안의 레이어 id는 새로 만든다.

## 내보내기·저장

- 내보내기 창에 "장면" 드롭다운을 둔다(기본 mainComp). 세트 내보내기(`set-tab.js`)에서 장면별로 고를 수 있게 한다.
- 프로젝트 파일 왕복, 자동 저장, 되돌리기 스냅샷(snapshots.js)에 comps가 들어가는지 확인한다.
- 부품(part.js)으로 내보내기/가져오기: 장면을 쓰는 레이어면 그 장면도 같이 담는다.

## 테스트 (`tests/r26-comps.spec.js`)

- 예전 문서 마이그레이션 후 렌더 픽셀 동일.
- 장면으로 묶기 전후 픽셀 동일. 그룹 → 장면 바꾸기 전후 픽셀 동일.
- 200×200 장면을 768 장면에 넣고 2배 크기: 장면 밖 부분은 잘림(그룹과 다름).
- 같은 장면 3번 사용 → 하위 장면 렌더 1번(통계로 확인).
- 순환 거부. 쓰이는 장면 삭제 거부.
- 장면 탭 열고 하위 장면 레이어 편집 → 상위 장면 결과에 반영. 되돌리기 순서.
- 장면 안 offset·speed(R22 time) 적용.
- 내보내기 장면 선택, 저장 왕복, 미리보기 = 내보내기.
