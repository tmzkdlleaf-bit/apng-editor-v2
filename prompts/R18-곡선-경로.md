# R18 — 곡선 이동 경로

지금은 위치 키와 키 사이를 항상 직선으로 이동한다(`core/anim/prop.js`가 x·y를 따로 보간).
화면에서 경로 점의 손잡이를 당겨 곡선으로 움직이게 하고, 경로 방향을 따라 회전하는 기능을 넣는다. R17까지 끝났다고 가정한다.

## 시작 전에

1. 읽을 파일:
   - `src/core/anim/prop.js`, `evaluate.js`, `seam.js`
   - `src/ui/canvas/gizmo.js`(motionPathKeyFrames, 경로 그리기), `path-edit.js`(경로 점 끌기, straightenPath), `hit.js`(getDocWorldTr, getParentWorldTr), `drag.js`, `transform.js`
   - `src/ui/motion-record.js`, `src/core/doc/commands.js`(moveKeys·retimeKeys·setKey·setProp)
   - `src/ui/inspector/layout-section.js`
2. 위치 x·y를 따로 계산하는 자리를 모두 찾아 목록으로 적는다(`evalProp(transform.x` / `transform.y` 검색).

## 데이터 구조

- 곡선 손잡이는 **`transform.x`의 키**에 붙인다. 형식: `key.sp = { ix, iy, ox, oy }`.
  - 단위는 문서 px이고, 그 키의 위치를 기준으로 한 상대값이다.
  - `i`는 들어오는 손잡이, `o`는 나가는 손잡이다.
  - x 키에 두는 이유: 키를 옮기는 기존 명령(moveKeys 등)이 키 객체를 통째로 옮기므로 손잡이도 같이 따라간다.
- 곡선 경로는 **x와 y 키가 같은 프레임들에 있을 때만** 쓴다. 맞지 않으면 지금처럼 직선 보간한다.
- `layer.autoOrient: false`를 추가한다. 경로 방향 따라 회전 기능이다.
- 문서 버전 +1.

## 항목

### R18-1. 위치 계산 (`core/anim/position.js` 새 파일)

- `evalPosition(transform, f)` → `{ x, y, angle }`.
  - x·y 키 프레임이 같고 `sp`가 하나라도 있으면: 키 사이를 3차 베지어 곡선 `P0, P0+o, P1+i, P1`으로 잇는다.
  - 곡선 위 진행 정도는 x 키의 이징으로 구한 비율을 **곡선 길이 비율**로 바꿔서 쓴다. 그래야 속도가 고르다.
    곡선 길이 표는 키 배열마다 한 번 만들어 WeakMap에 캐시한다(표본 32개 정도).
  - y 키의 이징은 곡선 구간에서는 쓰지 않는다. UI가 x·y 이징을 같이 바꾸게 한다.
  - `angle`은 그 지점의 진행 방향(도)이다.
  - 조건이 맞지 않으면 지금처럼 `evalProp`으로 x·y를 따로 계산한다. 결과가 기존과 비트 단위로 같아야 한다.
- `evaluate.js`의 `evalTransform`은 x·y를 이 함수로 구한다. `autoOrient`면 `rotation`에 `angle`을 더한다.
- 1단계에서 찾은 다른 x·y 계산 자리도 모두 이 함수를 쓰게 바꾼다.

### R18-2. 화면에서 손잡이 편집 (`path-edit.js`, `gizmo.js`)

- 편집 도구에서 경로 점을 고르면 손잡이 2개가 보인다(손잡이가 없으면 안 보인다).
- 조작:
  - Alt + 점 끌기: 손잡이를 새로 당겨 만든다(양쪽 대칭).
  - 손잡이 끌기: 반대쪽도 같은 직선 위로 따라 움직인다(부드러운 점).
  - Alt + 손잡이 끌기: 반대쪽은 그대로 둔다(꺾인 점).
  - 점 우클릭 메뉴: "부드러운 점으로", "꺾인 점으로(손잡이 없애기)"
- 모든 조작은 `begin → preview → commit`으로 되돌리기 1건이다.
- 경로 선은 프레임마다 점을 찍는 게 아니라 곡선 자체를 그린다(키 사이를 촘촘히 표본). 프레임 위치에는 작은 점을 따로 찍는다.
- 그룹 안 레이어·카메라 적용 상태에서도 손잡이 위치가 화면과 맞아야 한다. `getParentWorldTr`로 변환한다.

### R18-3. 속성 패널 (`layout-section.js`)

- 위치 아래에 경로 버튼 3개를 둔다:
  - "경로 부드럽게": 모든 중간 키에 자동 손잡이. 앞뒤 키 방향으로 키 간격의 1/3 길이.
  - "경로 직선으로": 모든 `sp` 지우기
  - "경로 따라 회전": `autoOrient` 켜기/끄기
- x·y 키 프레임이 맞지 않으면 "곡선 경로를 쓰려면 X·Y 키가 같은 프레임에 있어야 합니다" 안내와 [맞추기] 버튼을 띄운다.
  [맞추기]는 빠진 쪽에 현재 계산값으로 키를 넣는다.
- 기존 `straightenPath`(중간 키를 직선 위로 옮기기)는 그대로 둔다. 이름은 "중간 점을 직선 위로"로 바꾼다.

### R18-4. 함께 확인할 것

- 움직임 녹화(`motion-record.js`)는 손잡이를 만들지 않는다. 지금 그대로 둔다.
- 키 복사·붙여넣기, 키 늘이기(retime)에서 `sp`가 보존되는지 확인한다.
- 키 늘이기를 하면 손잡이 길이는 그대로 둔다. 공간 위치이므로 바뀌지 않는 게 맞다.
- 이음새 검사(`seam.js`): 곡선이어도 f0과 끝 프레임 값을 같은 함수로 비교하는지 확인한다.

## 테스트 (`tests/r18-path.spec.js`)

- `sp` 없는 문서: 위치 결과가 비트 단위로 동일(기존 테스트 통과).
- 키 3개 + 가운데 키 손잡이: 가운데 구간 위치가 직선에서 벗어난다(값으로 확인).
- 곡선 길이 비율: linear 이징이면 프레임 사이 이동 거리가 고르다(편차 기준 보고).
- `autoOrient`: 오른쪽으로 움직이면 0도, 아래로 움직이면 90도 근처.
- x·y 키 프레임이 다르면 직선 보간 + 안내 표시.
- 손잡이 끌기 되돌리기 1건, 저장 왕복, 미리보기 = 내보내기.
