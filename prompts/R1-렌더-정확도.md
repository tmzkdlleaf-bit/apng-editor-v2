# R1 — 렌더 정확도 (검토 보완 1)

코드 검토에서 "미리보기 배율·화면 잘라 그리기(view)·내보내기"에 따라 결과가 달라지는 버그를 찾았다.
`tests/r0-repro.spec.js`가 저장소에 들어 있다. 이 묶음은 그중 `[R1-*]` 테스트를 통과시키는 것이 목표다.
`[R2-*]`, `[R3-*]`는 다음 묶음이니 건드리지 않는다(실패한 채로 둔다).

CLAUDE.md 규칙을 그대로 따른다. 특히 렌더 규칙 1~5, "추측하지 말고 코드를 읽고 판단", 묶음 끝나면 보고하고 멈춤.

## 시작 전에

1. `npx playwright test tests/r0-repro.spec.js -g "R1-"` 를 돌려 4개가 실패하는 것을 먼저 확인하고, 실패 메시지를 보고에 적는다.
2. 아래 파일을 읽고 계획을 짧게 말한 뒤 시작한다.
   `src/core/render/frame.js`, `matrix.js`, `layers/*.js`, `mask.js`, `src/ui/export/index.js`, `src/ui/assets.js`, `src/ui/canvas/hit.js`

## 항목

### R1-1. 배율이 1이 아닐 때 그룹 자식·카메라 위치가 틀어짐

- 재현: 그룹 기준점 (50,50), 자식 x=70 → 배율 1: 65px, 배율 2: 15px, 배율 0.5: 90px (모두 65여야 함).
  카메라 x=20, 줌 1.5 문서도 배율마다 위치가 다름.
- 원인: `composeTransforms(parent, child)`가 `child.x - parent.x`를 하는데, `parent`는 `frame.js`에서
  `renderScale`이 곱해진 화면 픽셀(`camTr = { x: cam.x * renderScale, scale: zoom * renderScale }`)이고 `child`는 문서 픽셀이다.
  그룹 안 자식도 같은 이유로 틀어진다.
- 고칠 방향(방법은 코드를 읽고 정하되 아래 조건을 지킬 것):
  - 위치·회전·축척 합성은 모두 **문서 단위**로 하고, `renderScale`은 맨 마지막(레이어 렌더러에 넘기기 직전)에 한 번만 곱한다.
  - 그룹·인스턴스가 자식에게 넘기는 부모 변환도 문서 단위여야 한다(중첩 그룹 포함).
  - **배율 1일 때 결과는 지금과 픽셀 단위로 같아야 한다.** 기존 테스트 337개가 그대로 통과해야 한다.
    카메라 X/Y의 의미(지금은 줌 중심점)는 바꾸지 않는다. 의미를 바꾸는 것은 별도 결정 사항이다.
  - 이펙트 레이어(`effect.js`)의 `wx/wy`, 마스크(`renderMask`), 효과 소스 슬롯도 같은 기준으로 맞는지 확인한다.
  - `hit.js`의 `getDocWorldTr`(선택·기즈모용)는 같은 `composeTransforms`를 쓰지만 카메라를 넣지 않고 모션도 `null`로 계산한다.
    그래서 카메라 줌·이동이나 모션 클립이 있으면 선택 상자가 그려진 위치와 어긋난다. 렌더와 같은 합성(카메라·모션 포함)을 쓰도록 맞추고,
    클릭 판정(`hitTest`)과 기즈모가 실제 그림 위에 오는지 테스트한다. 일부러 뺀 것이라면 근거를 보고에 적는다.
- 추가 테스트(`tests/r1-scale.spec.js`): 아래 각 경우에 배율 1·2·0.5와 view(문서 일부만 그리기) 결과의 도형 위치가
  문서 단위로 ±1px 안에서 같은지 확인한다.
  그룹 기준점 이동 / 회전·축척된 그룹 / 그룹 안 그룹 / 카메라 x·y·줌 / 그룹 안 이미지(외곽선·흐림 경로) / 그룹 안 마스크 / 이펙트 box 범위.

### R1-2. 인스턴스 레이어가 view 렌더에서 사라짐

- 원인: `layers/instance.js`에 `group.js`의 `offCtx.translate(-viewOffsetX, -viewOffsetY)`가 빠져 있다.
- 오버라이드는 마스터의 직계 자식에만 적용된다(손자 레이어는 오버라이드 안 됨). 이 동작은 그대로 두되, 보고에 적는다.

### R1-3. 내보내기에서 움직이는 이미지(anim) 레이어가 빠짐

- 원인: `src/ui/export/index.js`의 `prepareDeps()`가 `getAnimFrames: () => null`.
- 고칠 방향: 문서에서 anim 레이어가 쓰는 에셋은 `core/io/anim-decode.js`의 `decodeAnim`으로, image 레이어 에셋은 `createImageBitmap`으로 준비한다.
  인스턴스·그룹 안의 레이어도 빠짐없이 모은다. 창을 닫을 때 만든 비트맵은 `close()`한다.
- 추가 테스트: 실제 내보내기 창 경로(`window.__exportUI`)로 anim 레이어만 있는 문서를 내보내서,
  디코드한 결과 프레임에 불투명 픽셀이 있고 프레임마다 내용이 달라지는지 확인한다.

### R1-4. 글자 정렬 잘림 / 글자 간격에 따라 정렬이 바뀜

- 재현: 48px 한글 14자(폭 약 672px) 왼쪽 정렬이 603px에서 잘림. 글자 간격 0.001이면 왼쪽 정렬이 가운데로, 오른쪽 정렬은 오른쪽으로 밀림.
- 원인 1: `layers/text.js`의 `_textContentSize`가 폭을 `글자수 × 1.8 × 크기`로 어림하고 가운데 기준으로 굽는다. 왼쪽/오른쪽 정렬은 한쪽으로만 뻗어서 반쪽 폭을 넘는다.
- 원인 2: `_lineStartX`가 left는 `-W/2`(가운데처럼), right는 `+W/2`를 돌려준다. left는 `0`, center는 `-W/2`, right는 `-W`여야 하고, W는 마지막 글자 뒤 간격을 빼야 한다.
- 고칠 방향:
  - 폭은 `measureText`로 실제로 잰다. core는 DOM을 못 쓰므로 측정용 `OffscreenCanvas(1,1)` 하나를 **모듈에서 한 번만** 만들어 재사용한다
    (렌더마다 새로 만들지 않음 — 렌더 규칙 4). 폰트가 늦게 로드돼도 `stage.js`의 기존 `loadingdone` 처리로 캐시가 비워지는지 확인한다.
  - 정렬에 따라 콘텐츠 캔버스 안의 기준점 위치를 맞춘다(왼쪽 정렬이면 왼쪽 끝, 오른쪽 정렬이면 오른쪽 끝).
  - `measureTextBounds`(선택 상자·클릭 범위)도 같은 실측값과 같은 기준점을 쓰게 하고, 기즈모가 정렬에 맞게 그려지는지 확인한다.
- 같이 고칠 것(낮음):
  - 글자별 그리기 경로의 그림자: 캔버스 그림자는 확대를 따르지 않으므로 `shadowOffsetX/Y`, `shadowBlur`에 현재 배율을 곱해 정적 경로와 같은 크기로 보이게 한다.
  - `_wordReveal`이 줄바꿈 문자를 글자 수에 넣어서 줄 수만큼 더 보이는 문제.
  - 글자를 `line[ci]`로 돌면 이모지 같은 2칸 문자가 쪼개진다. `[...line]`으로 통일한다(`_lineStartX`와 기준을 맞춤).
- 추가 테스트(`tests/r1-text.spec.js`): 정렬 3종 × 글자 간격 0/2 × 정적/타자기 조합에서 그려진 범위가 실측 폭과 맞고(잘림 없음),
  같은 정렬끼리 위치가 ±3px 안에서 같은지. 선택 상자 폭이 실측 폭 + 여백 수준인지.

  (성능 테스트 s5-1/s5-2가 기계 부하로 실패하면 다시 돌려 보고, 반복 실패면 보고에 숫자를 적는다.)
- CLAUDE.md 형식대로 보고하고 멈춘다. "직접 확인하는 방법"에는 다음을 꼭 넣는다.

  - 움직이는 이미지가 든 문서를 내보내 파일에서 움직이는지
  - 한글 긴 글자를 왼쪽/오른쪽 정렬했을 때 잘리지 않는지
