# R28 — 새 효과 (공포·TRPG / 그림 변형 / 장면 전환 / 자연·날씨)

새 효과를 다섯 부분(R28a~e)으로 나눠 **순서대로 이어서** 만든다.
이 묶음에 한해, 사용자가 부분 사이에 멈추지 않고 이어 가는 것을 승인했다. 부분마다 `npm test`를 통과시키고 커밋한 뒤 바로 다음 부분으로 간다.
다만 아래 경우에는 그 자리에서 멈추고 보고한다:
- 테스트를 통과시킬 수 없을 때
- 문서 구조(schema·migrate)를 바꿔야 할 때
- 계약(효과·모션 계약, renderFrame)을 바꿔야 하는데 이 파일에 적힌 범위를 넘을 때

**R27(풀 흔들림·효과 정비)이 커밋된 뒤에 시작한다.** R27의 공용 함수(바람 모델, "밝은 배경용")를 그대로 쓴다.
`git log`에 `R27`(또는 `R27b`)이 없으면 시작하지 말고 그 사실만 보고하고 멈춘다.

## 진행 기록

`prompts/R28-진행.md`를 만들고 표로 관리한다. 부분을 끝낼 때마다 갱신·커밋한다. 중간에 대화가 끊겨도 이 표를 보고 이어서 할 수 있어야 한다.

| 부분 | 내용 | 상태 | 커밋 | 테스트 수 | 메모(성능·막힌 점) |
|---|---|---|---|---|---|

부분을 끝낼 때마다 이 파일에 짧은 보고(만든 파일, 테스트 결과, 프레임당 ms, 바꿀 수 있는 기본값)를 덧붙인다. 마지막에 CLAUDE.md 형식으로 전체 보고를 한 번 한다.

## 모든 새 효과에 공통인 규칙

- CLAUDE.md 렌더 규칙: 결정론(seed 난수기만), `ctx.filter` 금지, 렌더 경로에서 캔버스 새로 만들지 않기(풀 borrow/release), 미리보기와 내보내기가 같은 `renderFrame`.
- **반복(루프)형**은 frame 0 = frame N. 속도는 "한 번 재생 동안 몇 번"(정수). 무작위로 번쩍이는 것(번개 등)도 루프 길이 안에서 같은 순서로 반복한다.
- **한 번(once)형**(전환·깨짐·터짐)은 루프 검사에서 빼는 표시를 계약에 두고, 내보내기 때 등장/퇴장 모션과 같은 경고를 띄운다(28a 참고).
- 파라미터는 R16 규칙대로 키프레임을 넣을 수 있다. 좌표(중심·초점)는 `coord` 형식으로 캔버스에서 끌 수 있게 한다(R12 효과 좌표 끌기 방식).
- 밝은 배경에서 잘 안 보이는 효과에는 R27의 "밝은 배경용" 파라미터를 단다.
- 성능: 768×768, 기본값에서 **프레임당 8ms 이내**(소스를 받는 효과 포함). 넘으면 기본값(해상도·개수)을 낮추고 진행 기록에 적는다.
- 효과마다 `description`(언제 쓰는지 한 줄), 썸네일 프레임, `docs/effects.md` 목록 추가.
- 효과마다 테스트: 결정론(같은 프레임 두 번 → 픽셀 동일), 루프형은 이음매, 극값(파라미터 최소·최대에서 오류·NaN 없음), 성능. 기존 `s5-*` 자동 검사에 들어가면 그것으로 대신한다.
- 부분마다 `npm run sheets`로 견본 시트 갱신.
- 이름·분류·파라미터 기본값은 모두 "바꿀 수 있는 기본값"으로 보고한다.

# R28a — 공통 토대 (새 효과 없음)

뒤 부분에서 반복해서 쓸 것을 먼저 만든다. **기존 효과의 렌더 결과는 픽셀 단위로 그대로**여야 한다.

1. **한 번(once)형 표시**
   - 효과 계약에 `once: true`를 추가한다. 루프 이음매 검사 대상에서 빠지고, `getExportWarnings`가 "한 번 재생되는 효과가 있어 반복 재생 때 끊겨 보일 수 있다" 경고를 낸다(등장/퇴장 모션 경고와 같은 자리·문구 방식).
2. **진행 방식 공용 파라미터** (once형 효과가 공통으로 씀)
   - `진행 방식`: `자동`(시작 프레임 + 길이 프레임, 그 사이 0→1) / `직접`(`진행` 값 0~1을 키프레임으로).
   - `방향`: `나타나기` / `사라지기`(진행을 뒤집음).
   - `느리게 시작·끝`(이징): 기존 이징 목록 재사용.
   - `_fx-util.js`에 `progressOf(f, p)` 하나로 두고 모든 once형이 이걸로 진행값을 얻는다.
3. **소스 2개 받기 확인**
   - 카드 뒤집기(앞면·뒷면), 전환(나가는 화면·들어오는 화면)에 소스 2개가 필요하다. 지금 계약의 `sources: [{key,label}, …]`가 2개 이상을 지원하는지 확인하고, 안 되면 지원하게 한다(UI 소스 연결 칸 2개 포함).
4. **흐림 공용 함수**
   - 보정(`core/render/adjust.js`)에 있는 흐림 계산을 효과에서도 쓸 수 있게 `_fx-util.js`(또는 `core/render/blur.js`)로 꺼낸다. 반지름이 위치마다 다른 흐림(가장자리·미니어처용)을 위해 "흐림 단계 몇 장을 미리 만들어 섞기" 방식을 같이 준비한다.
   - 보정 레이어 흐림 결과는 픽셀 동일(기존 테스트로 확인).
5. **노이즈 경계 공용 함수**
   - 잉크 번짐·종이 불타기·혈관·금 가기에 쓰는 "노이즈 문턱값으로 번지는 경계"와 "가지치기 선(분기 선)"을 `_fx-util.js`에 공용 함수로 둔다.

테스트: `tests/r28a-base.spec.js` — once 표시 경고, `progressOf` 자동/직접/방향/이징, 소스 2개 연결 왕복(프로젝트 파일 저장·열기), 보정 흐림 픽셀 동일.

# R28b — 공포·TRPG 연출 (5종, 분류: `공포`)

| 이름 | 형 | 설명·파라미터 |
|---|---|---|
| 화면 금 가기 | once | 한 점에서 유리 금이 퍼진다. 중심(좌표), 갈래 수, 잔금 양, 퍼지는 진행, 금 색·밝은 테두리, 깨지는 순간 흔들림(0~1, 처음 몇 프레임만), 조각 어긋남(금 사이 화면을 살짝 밀기 — 아래 화면 소스가 연결됐을 때만). 진행 끝나면 금은 남는다. |

# R28c — 그림 변형 (5종, 분류: `변형`)

모두 소스(아래 레이어/그룹)를 받는다.

| 이름 | 형 | 설명·파라미터 |
|---|---|---|
| 그림자 | 정적(움직임은 키프레임) | 소스 모양대로 그림자. 거리, 방향(각도), 흐림, 색, 불투명도, 퍼짐(그림자 크기 키우기), 그림자만 보기. 그림자 아래·소스 위 순서로 합성. |
| 밝은 곳 번짐 | 정적/반복 | 소스에서 일정 밝기 이상인 부분만 빛처럼 번진다. 문턱 밝기, 번짐 반지름, 세기, 색 입히기(선택), 반짝이며 숨쉬기(반복, 0이면 없음). |
| 아지랑이 | 반복 | 열기처럼 화면이 위로 일렁인다. 세기, 일렁임 크기, 위로 흐르는 속도(정수), 적용 범위(아래쪽 몇 %부터 / 전체 / 가리기로 지정). |
| 모자이크 | 정적 | 칸 크기, 모양(네모·둥근 점·육각), 범위(전체 / 원·사각 영역 / 가리기로 지정), 영역 가장자리 부드럽게. |
| 부분 흐림 | 정적(초점은 키프레임) | 아래 5가지 모양을 한 효과의 `모양`으로 고른다. |

**부분 흐림 `모양`**
- `영역`: 원·사각형 안(또는 바깥, 뒤집기)만 흐림, 경계 부드럽기.
- `미니어처`: 가로 띠만 선명하고 위아래로 갈수록 흐림. 띠 위치·폭·기울기·흐려지는 거리.
- `가장자리`: 가운데는 선명, 가장자리로 갈수록 흐림(시야가 좁아지는 느낌). 선명한 범위, 흐려지는 거리.
- `움직이는 초점`: 선명한 점(좌표)을 키프레임으로 옮긴다. 선명한 반지름, 흐려지는 거리. 캔버스에서 초점 점을 끌 수 있게.
- `펜으로 지정`: 이 효과 레이어에 R21 펜 가리기를 그려 흐릴 곳을 정한다. 새 그리기 기능을 만들지 말고 **기존 가리기를 그대로 쓰고**, 속성 패널에 "가리기 탭에서 펜으로 흐릴 곳을 그리세요" 안내와 바로가기 버튼만 둔다. 가리기 경계 흐림(feather)이 흐림 경계로 자연스럽게 이어지는지 확인.
- 공통: 흐림 세기(최대 반지름). 28a 흐림 공용 함수 사용.

테스트 추가: 그림자 거리 0·흐림 0·퍼짐 0이면 소스 밖에 그림자 픽셀 없음(소스와 겹친 자리만). 부분 흐림 `영역`에서 영역 밖 픽셀은 소스와 동일. `미니어처` 띠 가운데 줄은 소스와 동일. 모자이크 칸 안 픽셀은 같은 색.

# R28d — 장면 전환 (7종, 분류: `전환`)

전환은 once형. 28a의 진행 방식(자동/직접, 나타나기/사라지기, 이징)을 쓴다.
소스: `나가는 화면`(필수), `들어오는 화면`(선택 — 없으면 투명 또는 색).

| 이름 | 설명·파라미터 |
|---|---|
| 잉크 번짐 전환 | 잉크 얼룩이 번져 화면을 덮었다가(또는 걷히며) 다음 화면이 나온다. 시작 점(여러 개 가능), 번짐 거칠기, 잉크 색, 가장자리 번짐, 튀는 방울. |
| 조각 흩어지기 | 화면이 조각으로 부서져 날아간다. 조각 수, 모양(불규칙 다각형·네모·삼각), 날아가는 방향(사방·한쪽·아래로 떨어짐), 회전, 순서(중심부터·한쪽부터·무작위), 사라질 때 흐려짐. |
| 종이 불타기 | 가장자리(또는 한 점)부터 타들어 가며 사라진다. 시작 위치, 타는 가장자리 색(빛나는 주황), 그을림 폭, 재 날림(작은 불티, R27 이후 불티 효과 재사용 가능하면). |
| 크리티컬 금빛 폭발 | 다이스 컷인용. 가운데서 금빛이 터진다: 번쩍(흰 화면) → 빛줄기 → 금가루·불티 → 고리 퍼짐 → 잔광. 중심, 색(금빛 기본, 펌블용 붉은색 예시 프리셋), 빛줄기 수, 가루 양, 고리 수, 전체 세기. **전환이 아니라 연출이므로 소스 없이도 쓴다**(소스가 있으면 번쩍 순간 소스를 밝게). |
| 카드 뒤집기 | 소스 2개(앞면·뒷면)를 카드처럼 뒤집는다. 축(세로·가로), 원근 정도(가짜 3D: 세로 띠마다 높이를 달리), 뒤집는 동안 살짝 떠오름, 광택이 지나감, 그림자. 뒷면이 없으면 앞면 좌우 반전 + 어둡게. |
| 홀로그램 등장·퇴장 | 투영되듯 나타나고 사라진다: 가로 줄무늬가 훑고, 깜빡이고, 색이 어긋났다가 맞춰짐. 기준 색(청록 기본), 줄무늬 간격, 깜빡임 횟수, 색 어긋남, 훑는 방향. |
| 홀로 코팅 (반복, once 아님) | 트레이딩 카드 홀로처럼 소스 모양 위로 무지개빛이 비스듬히 지나간다. 각도, 띠 폭, 무지개 범위, 반짝이 점(입자), 지나가는 횟수(정수), 세기, 무늬(매끈·별·다이아 격자). 기존 `홀로그램`(무지개 막 채우기)과 설명을 구분해 적는다. |

테스트 추가: 진행 0 = 나가는 화면과 픽셀 동일, 진행 1 = 들어오는 화면(또는 투명)과 픽셀 동일(전환 6종 전부). 카드 뒤집기 진행 0.5 근처에서 그려진 폭이 가장 좁음. 금빛 폭발은 소스 없이도 오류 없이 그려짐.

| 번개 | 반복 | 갈라지는 번갯불 + 화면 번쩍. 번개 수(한 번 재생에 몇 번), 위치 범위, 가지 수, 굵기, 색, 화면 번쩍 세기, 잔상(몇 프레임 남기). 28a 가지치기 선 사용. |
| 반딧불 | 반복 | 천천히 떠다니며 깜빡이는 빛 점. 개수, 크기, 색, 깜빡임 주기, 떠다니는 범위, 빛 번짐. 밝은 배경용 파라미터. |
| 오로라 | 반복 | 하늘에 일렁이는 빛 띠. 띠 수, 색 2~3개, 높이 위치, 일렁임 속도(정수), 세로 빛줄기 결, 세기. |
| 구름 흘러가기 | 반복 | 구름이 옆으로 흘러 지나감. 양, 크기, 높이 범위, 흐르는 방향, 한 번 재생에 몇 화면 지나가는지(정수 → 이음매), 색·그늘 색, 겹 수(뒤는 느리고 흐리게). |

### 비·눈 보강

기존 `비`, `눈`, `창문 빗물`에 파라미터를 **추가**한다. 새 파라미터의 기본값은 지금 모양과 픽셀 동일하게 둔다(옛 프로젝트가 그대로 보여야 함).

1. **종류(프리셋)**
   - 비: `기본`(지금) / `이슬비` / `소나기` / `장대비` / `진눈깨비`(비+눈 섞임)
   - 눈: `기본`(지금) / `싸락눈` / `함박눈` / `눈보라`
   - 종류를 고르면 양·크기·속도·바람 값이 그 종류 값으로 바뀐다(되돌리기 1건). 그 뒤 직접 고친 값은 유지. 종류 자체를 저장할지, 값만 바꾸는 버튼으로 둘지 판단해 보고.
2. **바닥 반응**
   - 비: 바닥선(세로 위치)에 닿으면 작은 물보라가 튄다. 바닥선 위치, 물보라 크기·양. 바닥 물웅덩이 동심원(파문, 양 조절, 0이면 없음).
   - 눈: 바닥선에 쌓인 눈 띠(두께·울퉁불퉁). **루프 규칙 때문에 시간이 지나며 점점 쌓이게는 하지 않는다**(frame 0 = frame N). 내려앉은 눈송이가 띠에 녹아들듯 사라지게.
3. **앞뒤 깊이**
   - 겹 수(1~3). 뒤 겹은 작고 느리고 흐리게, 앞 겹은 크고 빠르고 흐릿하게(가까워서 초점이 안 맞는 느낌). 겹 1 = 지금 모양.
4. **유리창 표현**
   - `창문 빗물` 보강: 맺힌 물방울이 커지다가 줄기로 흘러내리며 지나간 자리에 길이 남는 표현, 물방울 안에 뒤 화면이 뒤집혀 비치는 굴절(소스가 연결됐을 때만, 세기 0이면 없음).
   - 새 효과 `성에`: 창 가장자리부터 얼음 결정 무늬가 덮인다. 덮는 정도, 결정 결 크기, 색, 가운데 닦인 자리(원, 좌표·크기), 반복형(살짝 반짝임) 또는 once형(서서히 끼기) 선택.

테스트 추가: 비·눈·창문 빗물의 새 파라미터가 기본값이면 기존 견본·스냅샷 테스트와 픽셀 동일. 겹 수 3에서 결정론·루프. 바닥 반응 켰을 때 바닥선 아래로는 그리지 않음.
