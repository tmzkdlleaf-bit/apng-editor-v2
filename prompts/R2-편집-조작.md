# R2 — 편집 조작 버그 (검토 보완 2)

`tests/r0-repro.spec.js`의 `[R2-*]` 테스트를 통과시키는 묶음이다. R1은 끝났다고 가정한다.
CLAUDE.md 규칙을 따른다. 상태 규칙("문서는 store.apply로만", "드래그는 begin → 임시 값 → commit으로 기록 1건")을 특히 지킨다.

## 시작 전에

1. `npx playwright test tests/r0-repro.spec.js -g "R2-"` 로 실패를 확인하고 메시지를 보고에 적는다.
2. 읽을 파일: `src/core/doc/store.js`, `commands.js`, `src/ui/timeline/track-canvas.js`, `src/ui/keys.js`,
   `src/ui/shell/shell.js`(되돌리기 버튼), `src/ui/canvas/hit.js`, `src/ui/canvas/stage.js`, `src/ui/canvas/drag.js`

## 항목

### R2-1. 키프레임 여러 칸 끌기 / 늘이기

- 재현: f=2 키를 한 칸씩 4번 끌면 키는 그대로, 선택은 f=12 키로 넘어감(기대: 키 f=6, 선택 f=6).
- 원인: `_previewMoveKeys(delta)`가 `store.cancel()`로 원래 위치로 되돌린 뒤 `es.kfSelection`(이미 이전 delta만큼 옮겨진 프레임)을 기준으로 다시 옮긴다.
  `_previewStretch`도 같다.
- 고칠 방향: 드래그 시작 때 원래 선택(프레임)을 `_drag`에 저장해 두고, 미리보기는 항상 "원래 선택 + 이번 delta"로 계산한다.
  범위 막기(0 ~ frameCount-1)와 스냅(`_snapKeyDelta`)도 원래 선택 기준으로.
  끝난 뒤 되돌리기 1번이면 드래그 전 상태로 돌아가야 한다.
- `moveKeys` 명령은 옮긴 키가 선택 안 된 다른 키와 같은 프레임에 겹치면 같은 프레임 키가 2개가 된다(`retimeKeys`는 겹침 처리함).
  겹치면 옮긴 키가 이기도록 정리하거나, UI에서 막는다. 어느 쪽인지 보고에 적는다.
- 추가 테스트: 여러 번 나눠 끌기(오른쪽 4칸 → 왼쪽 1칸), 여러 레이어 키 함께 끌기, 늘이기를 여러 번 나눠 하기, 각각 되돌리기 1번에 원상복구.

### R2-2. 드래그 중 되돌리기·방향키

- 원인: `store.undo()/redo()`에 진행 중 묶음(`_batch`) 검사가 없다. 드래그 중 방향키는 `apply`가 예외를 던진다.
- 고칠 방향: `undo/redo`는 `_batch`가 있으면 아무것도 하지 않고 `null`을 돌려준다. `keys.js`의 방향키·삭제·복제 등 문서를 바꾸는 단축키도
  `store.isBatching()`이면 무시한다. 상단 되돌리기 버튼(`shell.js`)도 같은 규칙.
- 테스트: r0의 `[R2-2]` + 실제 화면에서 도형을 끄는 도중 Ctrl+Z / 방향키를 눌러도 콘솔 오류가 없고, 놓은 뒤 되돌리기 1번에 원래 위치.

### R2-3. 키 값만 바꿀 때 이징 유지

- 원인: `commands.js`의 `setProp`·`setCameraProp`가 `ease = 'linear'` 기본값으로 기존 키의 이징을 덮어쓴다.
- 고칠 방향: 기존 키가 있으면 `cmd.ease`가 **명시됐을 때만** 바꾸고, 없으면 기존 `ease`·`bezier`를 유지한다. 새 키는 지금처럼 `linear`.
  `setKey`도 기존 키를 통째로 `{ f, v, ease }`로 바꿔 `bezier`를 버리니 같이 확인한다.
- 호출하는 쪽(`edit-prop.js`, `path-edit.js`, `motion-record.js`, `layout-section.js`)이 일부러 ease를 넘기는 곳이 있는지 확인한다.

### R2-4. 캔버스 크기 바꾸기(가운데 맞춤) + 키프레임

- 원인: `resizeCanvas`가 `transform.x.value`만 더한다.
- 고칠 방향: 키가 있으면 모든 키의 `v`에 같이 더한다(`offsetProp`과 같은 방식).
  이펙트 `box` 범위 레이어, 카메라 X/Y(줌 중심점이므로 같이 옮겨야 화면이 같음)도 옮겨야 하는지 코드를 보고 판단해 보고한다.
- 되돌리기 1번에 원래 값으로.

### R2-5. 복제(duplicateLayers)

- 원인: 그룹과 그 자식을 같이 고르면, 자식은 `ids`에 있어서 `parentId`가 새 그룹으로 안 바뀌고 원래 그룹 순서에도 끼워진다.
- 고칠 방향: 선택 중 다른 선택의 자손인 id는 최상위 복제 대상에서 뺀다(`group` 명령이 이미 이렇게 함).
  복제 범위 안을 가리키는 `masterId`(인스턴스), `sources[].sourceId`(효과 소스), `mask.sourceId`는 새 id로 바꾼다.
- 테스트: r0 `[R2-5]` + 인스턴스·효과 소스가 복제본끼리 연결되는지.

### R2-6. 움직이는 이미지 클릭 판정

- `hit.js` 46줄 `assets.getAnimFrames?.(layer.assetId)?.[0]` → `?.frames?.[0]`.
- 테스트: r0 `[R2-6]` + 실제 화면에서 anim 레이어를 클릭하면 선택되는지.

### R2-7. 자동 절반 해상도가 안 풀림

- 원인: `stage.js`의 `_autoDraft`가 16ms 넘는 프레임 한 번에 켜지고 드래그가 끝날 때만 꺼진다.
- 고칠 방향(기본값 제안, 바꿀 수 있게 보고): 드래그·재생 중에만 자동 절반 해상도를 쓰고,
  드래그가 끝나거나 재생이 멈추면(또는 일정 시간 입력이 없으면) 한 번 원래 해상도로 다시 그린다.
  한 번 느렸다고 켜지지 말고 최근 몇 프레임 평균으로 판단한다. 에셋 첫 로딩 프레임은 판단에서 뺀다.
- 테스트: 무거운 효과(예: 색수차)를 켜서 느린 프레임을 만든 뒤 재생 정지 → 다음 그리기가 원래 해상도인지
  (`engine.stats().maxBorrowW` 또는 기존 테스트가 쓰는 방법으로 확인).
