# 전문가판 로드맵 (R16 ~ R26)

APNG 에디터 v2를 애프터 이펙트 수준의 전문 툴로 키우는 묶음 계획이다.
이 파일은 Claude Code가 각 묶음을 시작할 때 전체 그림을 알도록 `prompts/`에 둔다. 이 파일 자체는 붙여 넣지 않는다.

## 정한 방향

- 초보용 화면은 버리고 전문가 화면으로 통일한다.
- 순서: 효과 → 움직임 → 가리기·합성 → 화면 구성.
- 화면 구성(R23~R25)이 마지막이므로, R16~R22에서 만드는 UI는 **지금 속성 패널·타임라인에 임시로 넣는다.**
  대신 재사용 가능한 조각(시계 버튼, 속성 줄, 효과 파라미터 묶음)으로 만들어 R23~R24에서 자리만 옮기게 한다.

## 묶음 공통 규칙 (CLAUDE.md에 추가할 내용)

R16 시작 시 아래 내용을 `CLAUDE.md` 맨 아래 "전문가판 규칙" 절로 추가한다.

```
## 전문가판 규칙 (R16~)

- 움직일 수 있는 값은 모두 같은 모양: { value, keys: [{ f, v, ease, bezier? , ...}] }.
  v 의 종류: 숫자 / 좌표 {x,y} / 색 '#rrggbb' / 경로(R21) / 그 밖(문자열·참거짓 = 계단).
- 값 읽기는 src/core/anim/ 의 공용 함수 한 곳으로만 한다(evalProp, getProp, evalEffectParams, R20 이후 world.js).
  UI·렌더에서 layer.transform[key] 처럼 경로를 직접 파고드는 코드를 새로 쓰지 않는다.
- 새로 저장되는 필드는 schema.js 기본값 + migrate.js 버전 올림 + 프로젝트 파일 왕복 테스트를 같이 한다.
  예전 파일은 열었을 때 픽셀 단위로 같은 결과여야 한다.
- 새 기능이 꺼져 있으면(키 없음, 효과 쌓기 없음, 가리기 없음 등) 렌더 경로는 기존과 같아야 한다.
  기존 스냅샷·픽셀 테스트가 그대로 통과하는 것으로 확인한다.
- 복제·부품(part.js)·템플릿·변형(variants.js)이 새 필드를 잃지 않는지, 안에 든 id를 새로 바꾸는지 확인한다.
- R23 전까지 새 UI는 지금 속성 패널·타임라인에 넣되, 화면 위치와 분리된 조각으로 만든다.
```

## 묶음 진행 방식

- 묶음마다 `tests/r<번호>-*.spec.js` 테스트 파일을 새로 만든다.
- 시작 때 읽은 파일과 계획을 말하고, 끝나면 CLAUDE.md 보고 형식대로 보고하고 멈춘다.
- 묶음이 너무 크면 STEP 0에서 "a/b로 나누자"고 제안하고 멈춰도 된다(R17, R21, R24, R26은 나눌 가능성이 있다).
