# 실사 VFX 통합 지침 (R30)

근거 자료: `docs/vfx-research.md`(실제 VFX 리서치 자료집). 이 지침의 수치는 모두 거기서 왔습니다. 자료집에서 계산한 값은 "환산"으로 표시합니다.

**이 지침이 다루는 범위**
- 그림체가 '실사'일 때의 기준입니다. '반실사'는 이 지침의 구조(층·타이밍·마무리 처리)를 쓰되, 모양은 단순화해도 됩니다.
- '손그림'은 기존 `docs/vfx-reference-guide.md` 를 따릅니다.
- CLAUDE.md 규칙이 항상 우선입니다.
  - 결정적 RNG만 쓴다.
  - 0프레임 = N프레임.
  - `ctx.filter` 를 쓰지 않는다.
  - 캔버스는 풀에서 빌리고 돌려준다.
  - 한 프레임 8ms 목표.

**한 줄 요약:** 실제 크기와 속도로 움직이고(물리), 여러 층이 각자의 수명대로 살다 사라지며(게임 구조), 카메라로 찍힌 것처럼 마무리한다(촬영).

---

## 1. 세 기둥

### 기둥 A — 물리: "실제 크기·실제 속도"
1. **장면 크기 기준을 하나 둔다.** 공용 매개변수 `worldHeight`(화면 높이가 실제 몇 m인지)를 쓴다.
   - 기본은 3 m다(전신 인물 + 여유). 컷인처럼 얼굴만 크게 나오면 0.6 m 정도다.
   - 모든 속도·크기는 m 단위로 정하고, `pxPerM = h / worldHeight` 로 바꾼다.
2. **시간은 문서의 fps에서 계산한다.**
   - 한 프레임 = `1 / fps` 초(기본 12fps → 83 ms).
   - 실제 현상의 주기를 프레임 수로 바꿀 때 반올림하고, 루프에 맞게 정수배로 맞춘다(5장).
3. **기본값은 측정값을 쓴다.** 사용자가 바꾸는 값은 "실제 의미가 있는 것" 위주로 둔다(불 크기, 비 세기, 바람 세기). '속도', '깜빡 속도' 같은 추상 값은 가능하면 실제 값에서 자동으로 계산한다.

### 기둥 B — 게임 구조: "층 + 수명 + 변화 곡선"
1. **효과 = 여러 층(이미터).** 층마다 맡은 역할이 있다. 예: 불 = 불길·불티·연기·아지랑이·주변 빛.
2. **입자마다 수명이 있다.** 태어남 → 수명에 따른 변화(크기·색·불투명도) → 서서히 사라짐. 툭 끊기며 사라지는 것은 금지다.
3. **무작위는 범위로 준다.** 크기·속도·수명·회전을 모두 범위 안에서 뽑는다. 손그림 지침의 크기 3단계(큰 10%·중간 30%·작은 60%) 분포는 실사에서도 쓴다.
4. **힘은 실제 힘만 쓴다.**
   - 중력, 공기 저항, 부력(뜨거운 것이 위로), 바람
   - 작은 소용돌이(약하게. 세면 부자연스럽게 맴돈다)
5. **층끼리 이어진다.** 불길이 사라지는 자리에서 불티·연기가 태어나고, 부모 속도의 일부(연기는 약 50%)를 물려받는다.
6. **수명 순서를 지킨다.** 번쩍 < 불꽃·불티 < 불길 < 연기. 연기가 가장 오래 산다.

### 기둥 C — 촬영: "카메라로 찍힌 것처럼"
1. **움직임 흐림은 셔터로 계산한다.** 공용 매개변수 `shutter`(기본 180°)를 쓴다.
   - 흐림 길이 = 한 프레임 이동 거리 × (shutter / 360).
   - 180° = 절반. 90°는 더 또렷하고 끊기며, 360°는 더 흐리다.
2. **빛 번짐(블룸)은 문턱 없이 조금 섞는다.** 밝기에 비례하고, 효과 전체에 적용하며, 섞는 비율은 작게(기본 0.04~0.15) 둔다.
3. **입자감(그레인).** 실사 그림체 기본은 약하게 켠다.
   - 어두운 곳에 많고 밝은 곳에 적게 한다.
   - 매 프레임 바뀌되 루프 이음매가 없게 한다.
4. **검은색을 순흑으로 두지 않는다.** 연기·그림자 가장 어두운 색은 배경 쪽 색을 섞은 짙은 색이다.
5. **색수차·렌즈 플레어는 기본으로 끈다.** 넣는다면 아주 약하게 넣는다. 둘 다 유명한 CG 티다.
6. **조명 방향을 따른다.** 비는 역광일 때 보이고, 눈은 정면광에서 보인다. 연기는 역광에서 얇은 곳이 밝다. 효과마다 공용 매개변수 `lightDir`(빛 방향)와 `lightPos`(광원 위치, 선택)를 받는다.

## 2. 공용 도구 설계 (구현할 것)

새 파일은 `src/effects/_fx-real.js` 로 한다. `_fx-style.js` 와 함께 쓴다.

| 도구 | 하는 일 |
|---|---|
| `WORLD_PARAMS` | `worldHeight`(m), `shutter`(°), `lightDir`(각도), `grain`(0~1), `bloom`(0~1) 공용 매개변수 묶음. 실사·반실사에서만 보임 |
| `world(env, p)` | `{ pxPerM, dt(초/프레임), blurK(셔터 비율) }` 계산 |
| `emitter(spec)` | 결정론 이미터. 입자 i 의 태어난 시각 = (i / rate) 를 루프 길이로 접어서, 매 프레임 "지금 살아 있는 입자"만 계산한다(상태 저장 없이). spec 에 수명 범위·처음 속도 범위·힘·변화 곡선을 넣는다 |
| `integrate(p0, v0, forces, t)` | 중력·저항·부력에서 t 초 뒤 위치·속도를 닫힌 식으로 계산(저항은 지수 감쇠). 매 프레임 적분하지 않아 결정론이 유지된다 |
| `overLife(curve, u)` | 수명 0~1 에 따른 값. 곡선은 몇 개 점 배열 |
| `blackbody(T)` | 온도(K) → 색. 불·불티·불꽃 공용(자료집 2-1 온도표) |
| `streak(ctx, x, y, vx, vy, w, col, a)` | 셔터 흐림 선. 길이 = 속도 × dt × blurK. 앞쪽이 진하고 꼬리가 옅다 |
| `camera(ctx, env, p, draw)` | 촬영 마무리(블룸 섞기 → 그레인). 기존 `withDiffusion` 을 대체·확장 |
| `heatHaze(...)` | 아지랑이: 아래 화면 좌표를 노이즈 2개(크기·속도 다름)로 어긋나게. 효과 안에 넣을 때 쓴다 |

**결정론 규칙:** `emitter` 의 무작위 성질은 입자 번호 `i` 와 시드로 `hash2(i, k, seed)` 로 뽑는다. 프레임마다 rng 를 소비하는 순서에 기대지 않는다. 그래야 몇 번째 프레임을 그려도 같은 입자가 같은 성질을 갖는다.

## 4. 효과 분류와 적용 방법

이 에디터의 효과 약 85개를 셋으로 나눕니다.

### 4-1. 분류 A — 실제 현상 (세 기둥 모두 적용)
자료집에 수치가 있는 것은 그 값을 쓰고, 없는 것은 "추가 조사 필요"로 둔다.

| 효과 | 실제 기준 | 핵심 규칙 |
|---|---|---|
| `flame` 불꽃, `candle`, `spirit-flame` | 2-1 | 불 크기 → 깜빡임 자동. 바닥 흰~끝 빨강. 끝 위로 그을음 연기 층. 아지랑이 층. 촛불은 거의 안 깜빡임 |
| `sparks`, `fireworks`, 불티 | 2-2 | 흰색으로 태어나 식으며 노랑 → 주황 → 빨강. 중력 + 저항. 셔터 흐림 꼬리. 일부는 터져 조각남. 뜨겁고 빠른 무리 / 식고 느린 무리 |
| `smoke`, `fog`, `clouds` | 2-3 | 역광에서 얇은 곳 밝고 두꺼운 곳 어두움. 살면서 2~3배로 커짐. 가장 오래 삶. 검은색은 순흑 금지 |
| `critical-burst`, `shockwave`, `impact-flash` | 2-4 | 번쩍 1프레임 → 불덩이 빠르게 → 연기로 바뀌어 천천히. 충격파 층 필수. 층마다 시작·수명 다르게 |
| `rain`, `window-rain` | 2-5 | 길이 = 속도 × 셔터 시간(환산표). 역광·어두운 배경에서만 밝게. 줄 안에 밝기 얼룩. 화면에 보이는 비는 대부분 카메라 가까운 비 |
| 물보라(`rain` 안) | 2-6 | 1프레임만 반짝임 + 오래 가는 동심원 파문. 여러 프레임 자라는 왕관 금지 |
| `snow` | 2-7 | 점(약간 늘어난 점). 좌우 출렁임·팔랑임이 주된 움직임. 정면광 |
| `lightning` | 2-8 | 같은 줄기가 2~4번 다시 번쩍(번쩍 → 꺼짐 → 다시 약하게). 첫 번째가 가장 밝음. 화면 번쩍도 같은 박자 |
| `fireflies` | 2-10 | 켜짐 : 꺼짐 ≈ 1 : 7~9. 켜진 동안 위로 휨. 루프가 짧으면 일부만 켜짐 |
| `aurora` | 2-11 | 몇 초 루프에서는 아주 조금 움직임. 아래 초록, 위 빨강 |
| `heat-haze` | 2-12 | 노이즈 2개(크기·속도 다름), 위로 흐름, 열원 근처만 |
| `leaves`, `petals`, `bubbles`, `sandstorm`, `grass`, `wind-bend`, `ripple`, `caustics`, `frost`, `drip` | **추가 조사 필요** | 우선 기둥 B·C(층·수명·셔터 흐림·조명)만 적용 |

### 4-2. 분류 B — 카메라·렌즈 현상 (광학 규칙을 따름)

| 효과 | 규칙 |
|---|---|
| `sparkle`(실사), `lens-flare`, `bokeh`, `focus-sun` | 별빛 갈래 = 조리개 날 수 규칙(6·8·14·18). 모든 빛이 같은 방향의 갈래. 갈래 길이는 밝기에 비례. 날이 둥글면 둥근 빛점 |
| `bloom`, `glow` | 문턱 없이 밝기에 비례, 섞는 비율은 작게 |
| `grain` | 어두운 곳에 많고 밝은 곳에 적게. 매 프레임 다르게(루프 이음매 없이) |
| `chromatic` | 화면 가장자리·밝고 어두운 경계에서만, 아주 약하게(기본값을 낮춘다) |
| `vignette`, `light-leak` | 실제 렌즈·필름 현상 크기로. 과하면 가짜 |

### 4-3. 분류 C — 판타지·연출 (실제 대응물이 없음)
`magic-circle`, `runes`, `energy-orb`, `magic-shield`, `aura`, `hologram`, `hud-ring`, `neon`, `glitch`, `comic-flash`, `speed-lines`, 공포(`crack`, `veins`, `madness`, `pulse-border`), 전환(`ink-wipe`, `paper-burn`, `shatter`, `card-flip`, `holo-transition`, `iris`, `wipe`, `curtain`) 등.

1. **가장 가까운 실제 현상을 기준으로 빌린다.**
   - 에너지·마법 빛 → 불꽃(스파크)·네온관·플라스마 빛
   - 공포 금 → 유리·얼음이 깨지는 모습
   - 종이 불타기 → 불 + 불티 + 그을음
   - 잉크 → 물에 퍼지는 잉크
   - 빌린 현상의 수치는 "추가 조사 필요"로 둔다.
2. 기둥 B(층·수명)와 기둥 C(셔터 흐림·블룸·그레인)는 모두 적용한다.
3. 실사 그림체가 어울리지 않는 효과(`comic-flash`, `speed-lines`, `emotes`, `countdown` 등 만화 기호)는 `look` 을 두지 않는다.

## 5. 루프와 실제 시간이 부딪칠 때

APNG는 1~3초짜리 루프가 많아서, 실제 주기와 맞지 않는 일이 생깁니다.

1. **루프보다 짧은 현상은 정수배로 맞춘다.** 불 깜빡임, 번개 박자가 여기에 해당한다. 실제 주기에서 가장 가까운 "루프 길이 ÷ 정수"를 고른다. 오차는 ±20% 안이면 허용한다.
2. **루프보다 긴 현상은 일부만 보여 준다.** 반딧불 주기 5~7 s, 오로라가 여기에 해당한다. 입자마다 위상을 흩어서, 루프 안에서 일부만 켜지고 일부는 꺼진 채로 둔다.
   - 그래도 0프레임 = N프레임이 되도록, 각 입자의 켜짐 구간이 루프 안에서 닫히게 한다.
3. **프레임으로 못 그리는 빠르기는 흐림으로 바꾼다.** 12fps에서 6 Hz보다 빠른 깜빡임이 그렇다. 깜빡임을 그리지 않고 밝기 흔들림을 작게, 흐림을 크게 한다. fps를 올리면 자동으로 깜빡임이 보이게 한다.
4. **1프레임보다 짧은 사건은 1프레임에만 둔다.** 물보라, 번개 한 번이 그렇다. 사라지는 쪽은 잔상(파문·잔광)이 맡는다.

## 6. 구현 순서

> 진행 상황: 1번(공용 도구 `_fx-real.js`)과 2번(불꽃·비·번개·반짝임) 완료 — R30. `docs/effects.md` R30 참고.

1. 공용 도구 `_fx-real.js` + 테스트를 만든다. 결정론, 루프, `integrate` 닫힌 식, 셔터 흐림 길이를 확인한다.
2. 분류 A 대표 4개로 검증한다: 불꽃 · 비 · 번개 · 반짝임(실사).
   - 기존 R29b 실사 코드를 이 지침으로 다시 짠다.
   - 이전/이후 비교 이미지와 수치 검사(5-2 체크리스트)를 남긴다.
3. 분류 A 나머지 → 분류 B → 분류 C 순서로 진행한다.
4. "추가 조사 필요" 항목은 해당 효과 차례가 오기 전에 조사해 자료집에 추가한다.

## 7. 검수 체크리스트

### 7-1. 눈으로 보는 검사 (프레임 시트 + 움직임)
1. [ ] 실제 크기로 보이는가? (`worldHeight` 를 바꾸면 속도·크기가 함께 바뀌는가)
2. [ ] 층이 2개 이상이고, 층마다 수명이 다른가? (연기가 가장 오래 사는가)
3. [ ] 모든 입자가 서서히 사라지는가? (툭 끊김 없음)
4. [ ] 빠른 것에 셔터 흐림이 있고, 느려지면 점이 되는가?
5. [ ] 조명 방향을 따르는가? (비는 역광에서, 눈은 정면광에서 잘 보임)
6. [ ] 블룸이 밝은 곳에만 은은하게 생기고 화면이 뿌옇지 않은가?
7. [ ] 순흑·순백·채도 100% 원색이 없는가? (흰 핵 한 점은 예외)
8. [ ] 색수차·플레어가 꺼져 있거나 거의 안 보이는가?

### 7-2. 수치 검사 (테스트로 자동화)
1. [ ] 빗줄기 길이: 환산값 ±20% 안 (worldHeight·fps·shutter 기준)
2. [ ] 물보라: 1~2프레임 안에 사라짐 (파문 제외)
3. [ ] 번개: 한 번 칠 때 같은 줄기가 2번 이상 다시 밝아짐, 첫 번째가 가장 밝음
4. [ ] 불 깜빡임: 불 크기에 따른 주파수 ±20% (fps 한계 안에서)
5. [ ] 반딧불: 켜짐 비율이 전체 시간의 8~15%
6. [ ] 반짝임(실사): 갈래 수가 선택한 조리개 날 수 규칙과 같음
7. [ ] 공통: 결정론, 0프레임 = N프레임, `ctx.filter` 없음, 768px에서 한 프레임 8ms 목표(그래픽 카드 없이 잰 값은 12ms까지 허용, 넘으면 기록)
